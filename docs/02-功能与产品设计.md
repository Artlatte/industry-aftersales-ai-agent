# 电商售后客服智能体 — 功能与产品设计

> 覆盖三大核心能力：对话交互、知识库上传、插件迭代，附功能清单与优先级。

---

## 1. 对话交互

### 1.1 能力说明
- 理解用户售后诉求，多轮追问补齐必要信息。
- 回答必须**有据可依**：政策类回答引用知识库来源，业务类回答来自工具数据。
- 危险/敏感操作只给指引并转人工，**不做资金变更**。

### 1.2 交互流程（示例）

```
用户：我要退货
 └─ 智能体：识别「退货」意图
      ├─ 缺信息 → 追问：订单号/手机号？退货原因？
      ├─ 检索知识库 → 命中「7 天无理由退货」政策（带来源）
      ├─ 调订单插件 → 校验订单状态是否可退
      └─ 综合回复：政策 + 该订单的退货资格 + 下一步指引
```

### 1.3 功能需求清单

| 编号 | 需求 | 说明 | 优先级 |
| --- | --- | --- | --- |
| CH-01 | 意图识别 | 退货/退款/物流/咨询/投诉 等意图 | P0 |
| CH-02 | 多轮追问 | 缺订单号、缺原因时主动追问补全 | P0 |
| CH-03 | SOP 应答 | 按售后标准流程应答、话术规范 | P0 |
| CH-04 | 来源引用 | 政策回答标注知识库来源 | P0 |
| CH-05 | 业务数据直连 | 订单/退款/物流必须调工具，不得编造 | P0 |
| CH-06 | 转人工兜底 | 资金敏感/重大客诉/检索无命中时转人工 | P0 |
| CH-07 | 会话记忆 | 同会话内记住订单号等上下文 | P1 |

### 1.4 话术与边界规范（示例）
- 称呼友好、语气克制，不使用绝对化承诺（如「一定」「保证」）。
- 政策引用统一格式：`根据《XXX政策》（来源：知识库）…`。
- 业务数据统一格式：`您的订单 [订单号] 当前状态为 [状态]。`
- 触及资金变更 / 无法判定时：`该操作需人工协助，已为您转接。`

## 2. 知识库上传

### 2.1 能力说明
- 业务方**自助上传**政策/FAQ 文档，无需开发介入。
- 上传后即时可检索、可溯源、可删除，支持标签分类。

### 2.2 上传管线

```
上传(标题+正文+标签) → 格式校验 → 分块 → 归一化 → 建索引 → 可检索
```

### 2.3 功能需求清单

| 编号 | 需求 | 说明 | 优先级 |
| --- | --- | --- | --- |
| KB-01 | 知识上传 | 传入标题/正文/标签，写入知识库 | P0 |
| KB-02 | 自动分块 | 按段落/长度切分，控制单块大小 | P0 |
| KB-03 | 语义检索 | 按关键词/标签打分，返回 top-k 相关片段 | P0 |
| KB-04 | 来源溯源 | 每个命中片段带来源标题 | P0 |
| KB-05 | 知识列表 | 查看知识库目录（标题/标签/分块数） | P0 |
| KB-06 | 知识删除 | 删除过期知识，避免陈旧误导 | P1 |
| KB-07 | 标签过滤 | 检索时按标签缩小范围 | P1 |
| KB-08 | 浏览器上传 UI | 可视化上传/管理界面 | P2（需客户端授权） |

### 2.4 检索结果示例

```
query: 七天无理由退货
结果:
 1. [0.82] 《7天无理由退货政策》— "自签收之日起 7 日内，商品不影响二次销售可申请无理由退货…"
 2. [0.61] 《运费承担规则》— "无理由退货时，退回运费由买家承担…"
```

## 3. 插件迭代

### 3.1 能力说明
- 把业务能力拆成**独立插件**（订单/退款/物流/工单…），互不耦合。
- 每个插件支持**版本化**：新版本上线、异常回滚、灰度发布。

### 3.2 插件清单

| 插件 | 工具 | 说明 | 版本演进示例 |
| --- | --- | --- | --- |
| 订单插件 | order_lookup | 查订单状态 | v1 基础查询 |
| 退款插件 | refund_status | 查退款进度 | v1 基础进度 |
| 物流插件 | shipping_query | 查物流轨迹 | v1 基础轨迹 |
| 工单插件 | complaint_escalate | 生成投诉工单 | **v2 新增** |
| 知识库插件 | kb_upload/kb_search/kb_list/kb_delete | 知识上传与检索 | v2 加删除+标签过滤 |

### 3.3 迭代机制

```
定义 v1 → 运行 → 验证
            ↓ 发现问题 / 新增需求
定义 v2（不覆盖 v1，追加新版本）→ 更新上线
            ↓ 异常
回滚到 v1（旧版本始终保留）
```

**核心约束**：
- 旧版本**不可覆盖**，只追加新版本，保证可回滚。
- 单个插件失败不影响其他插件。
- 插件下线时自动移除其注册的工具与副作用（生命周期可逆）。

## 4. 功能优先级总览

| 优先级 | 定义 | 内容 |
| --- | --- | --- |
| P0 | 上线必备 | 对话 SOP、知识上传/检索/溯源、订单/退款/物流查询、转人工 |
| P1 | 首轮迭代 | 知识删除、标签过滤、会话记忆 |
| P2 | 后续增强 | 浏览器上传 UI、投诉工单、向量化检索 |
