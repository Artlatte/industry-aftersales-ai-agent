# 电商售后客服智能体 — 项目方案与总体架构

> 面向电商售后场景的**行业专属轻量级智能体**，具备「对话交互 + 知识库上传 + 插件迭代」三大能力。

---

## 1. 项目背景

电商售后是客服压力最集中、话术最重复、最容易标准化的场景之一：

| 痛点 | 现状 | 智能体价值 |
| --- | --- | --- |
| 咨询量大且重复 | 大量「怎么退货 / 退款多久到 / 物流到哪」类问题 | 7×24 秒级响应，分流 60%+ 标准咨询 |
| 政策零散难统一 | 退换货、运费、时效规则散落在不同文档 | 知识库统一沉淀，回答有据可依 |
| 业务系统割裂 | 查订单、查退款、查物流要切多个系统 | 插件打通订单/退款/物流，一站式查询 |
| 新人上手慢 | 话术、流程靠老带新 | 智能体内置 SOP，辅助新人快速上岗 |

**适用用户**：电商平台的售后客服团队、商家客服外包团队、需要快速部署行业助手的交付团队。

## 2. 能力概览

1. **对话交互**：多轮售后咨询，理解意图、追问补全、按 SOP 应答、异常转人工。
2. **知识库上传**：业务方可自助上传政策/FAQ 文档，即时可检索、可溯源、可删除。
3. **插件迭代**：订单/退款/物流/工单等能力以插件形式独立演进，支持版本化上线、回滚、灰度。
4. **测试闭环**：配套功能测试用例、执行报告、缺陷闭环，保证质量可度量。
5. **开箱即用**：以预设形式发布，一键部署到 DeepSeek Harness，新会话即用。

## 3. 行业场景定义

聚焦三个高频售后子场景：

| 场景 | 典型诉求 | 所需能力 |
| --- | --- | --- |
| 售后退换货 | 7 天无理由、质量问题、换货流程、运费承担 | 知识库（政策）+ 订单插件 |
| 退款进度 | 退款到账时效、退款单状态 | 知识库（时效）+ 退款插件 |
| 物流查询 | 发货没、到哪了、丢件 | 物流插件 + 知识库（赔付规则） |

**对话边界（明确不做什么）**：涉及资金敏感操作（直接退款/改价）、重大客诉（群体性投诉）时，智能体只给指引并**转人工**，不做自动资金变更。

## 4. 总体架构

采用「轻量级、可解释、可快速迭代」的分层架构：

```
┌─────────────────────────────────────────────────────────────┐
│                        对话交互层 (Chat)                      │
│   意图识别 · 多轮追问 · SOP 话术 · 转人工兜底 · 来源引用        │
└───────────────┬───────────────────────────────┬─────────────┘
                │                               │
        ┌───────▼────────┐              ┌───────▼────────┐
        │  知识库检索层    │              │  工具/插件编排层 │
        │  (RAG 轻量检索) │              │  (Tool/Plugin) │
        │ 分块·索引·打分  │              │ 订单·退款·物流 │
        └───────┬────────┘              └───────┬────────┘
                │                               │
        ┌───────▼───────────────────────────────▼────────┐
        │               LLM 编排层（模型路由 + 提示词）     │
        └───────┬───────────────────────────────┬────────┘
                │                               │
        ┌───────▼────────┐              ┌───────▼────────┐
        │   知识库存储     │              │   业务数据层     │
        │ (政策/FAQ 文档) │              │ (订单/退款/物流) │
        └────────────────┘              └────────────────┘

                        测试层（贯穿全程）
        功能测试 · 用例库 · 自动化脚本 · 报告 · 缺陷闭环
```

### 4.1 各层职责

| 层 | 职责 | 关键实现 |
| --- | --- | --- |
| 对话交互层 | 理解意图、组织多轮、约束话术 | 人设提示词 + SOP 规则 + 转人工规则 |
| 知识库检索层 | 把政策文档变成可检索片段 | 上传→分块→索引→打分→top-k 返回 |
| 工具/插件编排层 | 把业务能力封装为可调用工具 | 订单/退款/物流/工单插件，独立迭代 |
| LLM 编排层 | 综合「检索片段 + 业务数据」生成回答 | 提示词组装 + 来源引用约束 |
| 存储层 | 持久化知识与业务数据 | 知识库文件 + 业务数据接口 |
| 测试层 | 保障质量、推动闭环 | 用例/执行/报告/缺陷管理 |

### 4.2 「轻量级」的选型原则

| 原则 | 说明 |
| --- | --- |
| 无重依赖 | 检索采用关键词/词元打分，**不强制引入向量库**，降低部署门槛 |
| 可解释 | 检索命中可追溯来源，业务数据必须来自工具而非模型编造 |
| 可快速迭代 | 每个能力 = 一个插件，独立版本化，上线/回滚互不影响 |
| 可度量 | 每条回答标注来源，测试用例覆盖异常路径 |

> 演进路线：当知识规模增长、语义匹配要求变高时，可在检索层平滑升级为「embeddings + 向量库」混合检索，上层接口不变。

## 5. 技术选型

| 模块 | 选型 | 说明 |
| --- | --- | --- |
| 智能体框架 | DeepSeek Harness（Cordis 插件化） | 预设 = 人设 + 工具组合；插件支持版本化迭代 |
| 模型 | 可配置 LLM 路由 | 对话生成 + 检索重排 |
| 知识库检索 | 轻量关键词打分（词元重叠 + 标签加权） | 无向量库依赖，可离线 |
| 业务插件 | 订单 / 退款 / 物流 / 工单工具 | 接口契约 + Mock 数据，生产换真实接口 |
| 存储 | 知识库 JSON 文件 / 业务数据接口 | 轻量、可迁移 |
| 测试 | 用例库 + 功能测试 + 缺陷闭环 | 覆盖对话、检索、插件、异常 |

## 6. 关键角色与交付

| 角色 | 职责 |
| --- | --- |
| 智能体搭建者（开发者） | 搭建智能体、维护知识库与插件、执行测试 |
| 业务方（商家/客服） | 上传知识、确认话术、验收测试 |
| 客服团队 | 使用智能体、上报问题、参与回归 |

**交付物**：可运行智能体 + 知识库（含样本）+ 业务插件 + 测试用例与报告。
