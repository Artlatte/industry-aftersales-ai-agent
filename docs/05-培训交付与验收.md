# 电商售后客服智能体 — 培训交付与验收

> 对应岗位职责①的「3–5 天系统培训」：从认知到上线验收的全流程培训大纲，附里程碑、风险与验收标准。

---

## 1. 3–5 天培训方案

### 第 1 天：认知与需求对齐
- 上午：智能体与 RAG 基础认知；售后场景痛点演示；明确目标与边界。
- 下午：需求梳理——确定首批知识（政策/FAQ）、首批插件（订单/退款/物流）、话术与转人工规则。
- **产出**：需求清单 + 边界清单。

### 第 2 天：搭建与数据准备
- 上午：搭建智能体框架；配置人设与 SOP；准备知识样本并完成首次上传。
- 下午：接入业务插件（订单/退款/物流），用 Mock 数据联调。
- **产出**：可对话的智能体 v0.1 + 知识库初版。

### 第 3 天：测试与问题闭环
- 上午：讲解测试用例设计；执行功能测试（对话/知识/插件/异常）。
- 下午：登记缺陷、定位问题、修复并回归；输出测试报告。
- **产出**：测试用例 + 测试报告 + 缺陷闭环记录。

### 第 4 天：优化与插件迭代
- 上午：根据测试结果优化提示词与知识；演示「插件迭代」（新增工单插件、知识删除/标签过滤）。
- 下午：上线演练——版本更新、回滚、灰度；验收用例走查。
- **产出**：优化版智能体 v0.2 + 迭代演练记录。

### 第 5 天（可选）：验收与交接
- 验收测试走查；培训答疑；交付文档与操作手册交接；制定后续运营计划。
- **产出**：验收报告 + 交接清单 + 运营建议。

## 2. 里程碑与排期

| 里程碑 | 内容 | 时间 |
| --- | --- | --- |
| M1 需求对齐 | 场景/知识/插件/边界确认 | 第 1 天 |
| M2 首版搭建 | 对话 + 知识库 + 插件跑通 | 第 2 天 |
| M3 测试闭环 | 用例/执行/报告/缺陷闭环 | 第 3 天 |
| M4 迭代优化 | 插件迭代 + 上线演练 | 第 4 天 |
| M5 验收交付 | 验收 + 交接 + 运营计划 | 第 5 天 |

## 3. 风险与应对

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 知识质量差 | 回答不准、误导用户 | 上传前审核 + 来源溯源 + 定期清理陈旧知识 |
| 模型幻觉 | 编造政策/数据 | 强约束「数据必来自工具」+ 无命中不编造 + 转人工 |
| 业务系统不稳定 | 查询失败 | 错误码降级 + 转人工 + 重试 |
| 需求蔓延 | 工期失控 | 明确 P0/P1/P2 优先级，分批交付 |
| 话术不合规 | 客诉/合规风险 | 话术规范 + 评测集抽检 + 敏感操作转人工 |
| 插件回归破坏 | 新版本引入缺陷 | 版本不可变 + 自动化回归 + 快速回滚 |

## 4. 验收标准

| 维度 | 验收标准 |
| --- | --- |
| 对话 | 三大场景（退换货/退款/物流）可多轮完成；政策回答带来源；敏感操作转人工 |
| 知识库 | 可上传/检索/溯源/删除；空库与无命中正确处理 |
| 插件 | 订单/退款/物流查询正确；不存在数据返回 NOT_FOUND 不编造；支持版本更新与回滚 |
| 测试 | 用例通过率达到约定阈值；致命/严重缺陷全部闭环；测试报告齐全 |
| 培训 | 参训人员可独立完成知识上传与插件更新；交付文档齐全 |
| 安全 | 不做资金变更；不编造业务数据；话术合规 |

## 5. 交付清单

1. 可运行智能体（人设 + 知识库 + 业务插件）
2. 知识库（含样本）与上传操作说明
3. 测试用例库 + 测试报告模板 + 缺陷闭环记录
4. 3–5 天培训材料（每日本课纲与产出）
5. 交接文档（架构、插件清单、版本记录、运营建议）
