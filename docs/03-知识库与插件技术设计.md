# 电商售后客服智能体 — 知识库与插件技术设计

> 技术实现细节：知识库检索算法、插件接口契约、数据模型与演进路线。

---

## 1. 知识库技术设计

### 1.1 上传管线

```
输入(title, content, tags?)
  → 1. 格式校验（标题/正文非空，长度上限）
  → 2. 分块（按段落优先，超长段落按句子切分，单块 ≤ 512 字）
  → 3. 归一化（统一全半角、去多余空白、大小写）
  → 4. 词元化（中文按字符 bigram + 英文按词，停用词过滤）
  → 5. 建索引（每块记录：docId, title, tags, tokens, 原文）
  → 6. 持久化（写入知识库文件，即时可检索）
```

### 1.2 索引结构

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | string | 文档唯一 ID |
| title | string | 文档标题（用于来源溯源） |
| tags | string[] | 分类标签（如「退货」「运费」「时效」） |
| chunks | array | 分块列表，每块含 `text`（原文）与 `tokens`（词元） |
| createdAt | number | 创建时间戳 |

### 1.3 检索算法（轻量级，无向量库）

```
score(doc, query) = α · 词元重叠分 + β · 标签匹配分

词元重叠分 = |query_tokens ∩ chunk_tokens| / |query_tokens|     （Jaccard 近似）
标签匹配分 = |query_tags ∩ doc.tags| > 0 ? 1 : 0

命中后按 score 降序取 top-k（默认 5），返回：
  [{ score, source, snippet }]
```

**参数**：α=0.9、β=0.1；top-k 默认 5、上限 10；score < 阈值(0.05) 视为无命中。

**优点**：无外部依赖、可离线、可解释、冷启动零成本。
**演进路线**：知识规模增长或语义模糊匹配需求出现时，升级为「embeddings 向量检索 + 关键词混合召回 + LLM 重排」，上层 `kb_search` 接口与返回结构不变。

### 1.4 关键边界
- 空知识库：`kb_search` 返回明确提示「知识库为空，请先上传」。
- 无命中：返回空结果 + 提示转人工/追问，**不编造政策**。
- 超大文档：单块与总长设上限，超限截断并提示。
- 陈旧知识：`kb_delete` 删除后立即不再参与检索。

## 2. 插件技术设计

### 2.1 插件架构原则

| 原则 | 说明 |
| --- | --- |
| 一个能力一个插件 | 订单/退款/物流/工单各自独立，解耦 |
| 版本不可变 | 旧版本不覆盖，只追加新版本，支持回滚 |
| 生命周期可逆 | 插件停止时自动注销工具与副作用 |
| 数据不编造 | 业务数据只能来自工具，缺失即明确返回「未查到」 |

### 2.2 工具接口契约

#### 订单插件 `order_lookup`
```
入参: { order_id?: string, user_phone?: string }   (二者至少其一)
出参: { orders: [{ order_id, status, product, amount, order_date }] }
错误: ORDER_NOT_FOUND（未查到，绝不编造）
```

#### 退款插件 `refund_status`
```
入参: { refund_id?: string, order_id?: string }
出参: { refunds: [{ refund_id, order_id, status, reason, amount, progress }] }
错误: REFUND_NOT_FOUND
```

#### 物流插件 `shipping_query`
```
入参: { order_id: string }
出参: { order_id, carrier, tracking_no, status, events: [{ time, location, description }] }
错误: SHIPPING_NOT_FOUND
```

#### 工单插件 `complaint_escalate`（v2 新增）
```
入参: { order_id: string, reason: string, severity: 'low'|'high' }
出参: { ticket_id, status: 'created', assignee, created_at }
```

### 2.3 统一错误处理

| 错误码 | 含义 | 处理 |
| --- | --- | --- |
| NOT_FOUND | 数据不存在 | 返回「未查到 + 请核实单号」 |
| INVALID_ARGS | 参数缺失/非法 | 返回校验提示 |
| SYSTEM_ERROR | 外部系统异常 | 返回「系统繁忙，请稍后或转人工」 |

**原则**：错误信息对用户友好、对模型可解析，任何情况下不返回伪造数据。

### 2.4 鉴权与降级
- 演示期：内置 Mock 数据（字面量）模拟订单系统。
- 生产期：插件调用真实订单系统 API，带鉴权；外部系统不可用时按错误码降级为「转人工」而非静默失败。

## 3. 数据模型

### 3.1 知识库条目

```jsonc
{
  "id": "kb_2026xxxx_001",
  "title": "7天无理由退货政策",
  "tags": ["退货", "时效"],
  "chunks": [
    { "text": "自签收之日起 7 日内，商品不影响二次销售可申请无理由退货…", "tokens": ["自","签收",…] }
  ],
  "createdAt": 1760000000000
}
```

### 3.2 订单 / 退款 / 物流 / 工单

```jsonc
// 订单
{ "order_id": "SO20260601001", "status": "已签收", "product": "蓝牙耳机", "amount": 199.0, "order_date": "2026-06-01", "user_phone": "138****0001" }

// 退款
{ "refund_id": "RF20260612001", "order_id": "SO20260601001", "status": "退款处理中", "reason": "质量问题", "amount": 199.0, "progress": "已通过审核，等待原路退回" }

// 物流
{ "order_id": "SO20260601001", "carrier": "顺丰速运", "tracking_no": "SF1234567890", "status": "运输中", "events": [{ "time": "2026-06-03 10:00", "location": "广州分拨中心", "description": "已发出" }] }

// 工单
{ "ticket_id": "TK20260613001", "order_id": "SO20260601001", "status": "created", "reason": "多次发货延迟", "severity": "high", "assignee": "售后一组" }
```

## 4. 提示词与编排设计

- **人设段**：售后客服角色 + 话术规范 + 知识库优先原则 + 业务边界 + 转人工规则。
- **检索段**：先调 `kb_search` 获取政策依据，再结合业务工具数据作答。
- **来源约束**：政策类回答必须标注来源标题；业务类回答必须注明数据来自工具。
- **禁止项**：不编造政策与业务数据、不做资金变更、不用绝对化承诺。
