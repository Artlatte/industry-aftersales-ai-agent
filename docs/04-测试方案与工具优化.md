# 电商售后客服智能体 — 测试方案与工具优化

> 覆盖测试策略、用例设计、功能执行、报告与缺陷闭环，以及测试环境搭建与工具优化。

---

## 1. 测试策略

AI 智能体测试与传统软件不同：**结果有随机性、质量与提示词强相关**。因此采用分层策略：

| 层级 | 目标 | 手段 |
| --- | --- | --- |
| 单元/接口层 | 工具与检索逻辑正确、确定性 | 直接调用工具断言返回（可 100% 自动化） |
| 功能层 | 对话/知识/插件功能符合需求 | 用例驱动 + 人工/脚本验证 |
| 回归层 | 插件迭代不破坏既有能力 | 核心用例自动化回归 |
| 端到端层 | 完整售后闭环可用 | 场景脚本走查 |
| 提示词评测 | 话术合规、不编造、来源引用正确 | 评测集 + 人工抽查 |

**关键原则**：
- 确定性能力（检索打分、工具返回、参数校验）做**强断言**，可自动化。
- 生成性能力（话术、自然语言）做**规则断言**（含关键信息、含来源、不含违禁词）+ 人工抽检。

## 2. 测试用例设计

### 2.1 知识库检索（确定性，可自动化）

| 用例 | 输入 | 预期 |
| --- | --- | --- |
| KB-01 | 空知识库调用 kb_search | 返回「知识库为空」提示 |
| KB-02 | 上传《7天无理由退货》后检索「无理由退货」 | 命中该文档，含来源标题，score>0 |
| KB-03 | 检索「完全不存在的主题xyz」 | 返回空/无命中，不编造 |
| KB-04 | 上传带标签「运费」的知识，按标签过滤 | 仅返回该标签文档 |
| KB-05 | 删除某知识后再检索 | 不再命中 |

### 2.2 业务插件（确定性，可自动化）

| 用例 | 输入 | 预期 |
| --- | --- | --- |
| OPS-01 | order_lookup 用存在的订单号 | 返回订单状态，字段完整 |
| OPS-02 | order_lookup 用不存在的订单号 | 返回 ORDER_NOT_FOUND，不编造 |
| OPS-03 | refund_status 用存在的退款单 | 返回退款进度 |
| OPS-04 | shipping_query 用存在订单 | 返回物流轨迹 |
| OPS-05 | order_lookup 只传手机号 | 返回该手机号关联订单 |

### 2.3 对话功能（规则断言 + 抽检）

| 用例 | 输入 | 预期 |
| --- | --- | --- |
| CH-01 | 「我要退货」 | 追问订单号/原因，检索退货政策 |
| CH-02 | 「订单 SO20260601001 退货」 | 结合政策 + 该订单状态作答，含来源 |
| CH-03 | 「我的退款到哪了」缺单号 | 主动追问退款单/订单号 |
| CH-04 | 询问「帮我直接退款」 | 不执行资金操作，转人工指引 |
| CH-05 | 询问政策类问题 | 回答标注知识库来源 |

### 2.4 异常与边界

| 用例 | 场景 | 预期 |
| --- | --- | --- |
| EDGE-01 | 知识库为空时问政策 | 提示暂无知识并转人工/追问 |
| EDGE-02 | 超大文档上传 | 分块 + 截断，不崩溃 |
| EDGE-03 | 外部系统不可用（模拟） | 返回「系统繁忙」降级，不伪造 |
| EDGE-04 | 非法参数（缺必填） | 返回参数校验提示 |

## 3. 功能测试执行

1. **测试准备**：搭建隔离测试环境 + 准备测试数据（订单/退款/物流样本 + 知识样本）。
2. **冒烟测试**：三大能力（对话/知识/插件）主链路先通。
3. **用例执行**：按 2.1–2.4 逐条执行，记录实际结果与截图。
4. **缺陷登记**：不通过项登记缺陷，定级（致命/严重/一般/轻微）。

## 4. 测试报告模板

```
# 测试报告
一、测试概要：版本 / 范围 / 环境 / 起止时间
二、用例统计：总数 / 通过 / 失败 / 阻塞 / 通过率
三、缺陷统计：按严重级别与模块分布
四、核心结论：是否满足上线条件
五、遗留问题与风险
```

**通过率口径**：`通过率 = 通过用例数 / 有效用例数`；存在致命/严重未闭环缺陷时不得上线。

## 5. 缺陷闭环

```
发现缺陷 → 登记(定级/复现步骤/期望/实际)
  → 指派 → 修复 → 回归验证 → 关闭（或重开）
```

**闭环约束**：
- 每个缺陷有唯一 ID、复现步骤、责任人、状态流转记录。
- 修复后必须回归原用例 + 关联用例。
- 未闭环缺陷阻塞上线，由测试负责人输出结论。

## 6. 测试环境搭建

| 项 | 做法 |
| --- | --- |
| 环境隔离 | 独立测试工作区，与生产数据隔离 |
| 数据准备 | 订单/退款/物流 Mock 数据 + 样本知识库，可一键重置 |
| 外部系统替身 | 用 Mock 替代订单系统，支持注入故障（不可用/超时） |
| 环境一致性 | 记录环境配置（模型版本、插件版本、知识库版本），可复现 |

## 7. 工具优化

| 工具 | 用途 | 收益 |
| --- | --- | --- |
| 确定性用例自动化脚本 | 自动跑知识/插件断言用例 | 回归效率提升，秒级出结果 |
| 测试数据生成器 | 一键生成/重置 Mock 数据 | 环境准备零成本 |
| 用例库（文档化） | 统一维护用例与预期 | 可复用、可交接 |
| 缺陷看板 | 跟踪缺陷状态流转 | 闭环可视化 |
| 提示词评测集 | 收集典型问题与期望回答 | 话术质量可度量 |
| 度量指标 | 通过率、缺陷密度、闭环时长 | 质量趋势可追踪 |
